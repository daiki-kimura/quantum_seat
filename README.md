# 量子乱数席ぎめツール by IBM Quantum, Qiskit, and IBM Bob

IBM Quantum の実機で事前に取得した量子乱数を使い、受付に来た人の席を1人ずつ決める、飲み会などの席決めアプリです。

## ✨ 特徴

- **実機の量子乱数**: 実機（Heron r2）で事前に測定した乱数を受付時に読み出して使います。受付中に IBM Quantum へは接続しないので、待ち時間なしで一瞬で決まります
- **受付型の席決め**: 来場者が来るたびに、空席から1席を量子乱数で決定します。取消・全体の配置換え・CSV出力に対応
- **演出**: 受付ではビンゴ風のアニメーション、全体の配置換えでは全画面の演出が流れます（どちらも見せ方だけの効果です）
- **乱数の見える化**: 乱数プールの残りビット数をリアルタイムのカウンターで表示し、ボタンに消費ビット数の目安を表示します
- **参加者リスト**: 名前の候補を画面から上書き保存できます。候補をタップして選んだあとも書き換えでき、リストにない名前もそのまま入力できます
- **自由な会場レイアウト**: 四角・丸（楕円）・多角形の机と席をドラッグ／クリックで配置できます。「入口」「ステージ」などの文字・矢印・線も書き込めます
- **名前が重ならない表示**: 席の名前は、他の名前や席と重ならない位置に自動で配置されます。席から離れた名前には補助線が付きます
- **一括配置**: 参加者リストの未着席の人を、「参加者リストの全員を受付する」ボタン1つで、量子乱数により空席へまとめて配置できます
- **IBM Quantum 風のダークUI**: Carbon デザインを参考にしたダークテーマ
- **仕組みの解説ページ**: 実行した量子回路と席の決め方を、アプリ内（`/about`）で図入りで説明しています

## 🚀 セットアップ

### 1. 必要な環境

- Python 3.10 以上（OpenSSL 版）
  - macOS 付属の Python 3.9 は LibreSSL のため、IBM Cloud に接続できません。例: `brew install python@3.12`
- IBM Quantum Platform のアカウント（乱数の取得時のみ使用）

### 2. IBM Quantum API トークンの取得

1. [IBM Quantum Platform](https://quantum.cloud.ibm.com/) にアクセスし、アカウントを作成またはログイン
2. 右上のアカウントアイコンから「Account settings」を開く
3. 「API token」セクションでトークンをコピー

### 3. インストール

```bash
git clone <repository-url>
cd quantum_seat

# 仮想環境を作成して有効化
python3.12 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

# 依存パッケージをインストール
pip install -r requirements.txt
```

### 4. 環境変数の設定

```bash
cp .env.example .env
```

`.env` を開き、`IBM_QUANTUM_TOKEN` に取得したトークンを設定します（`.env` は `.gitignore` 済みです）。

### 5. 量子乱数を実機から取得する（イベントの前に）

```bash
python fetch_quantum_pool.py
```

待ち行列が最も短い実機を自動で選び、100 マップ（100 量子ビット × 100 ショット = 10,000 ビット）を1ジョブで取得して `data/random_pool.json` に追加します。所要時間は数分程度です。受付はこのファイルから順に読み出し、読んだビットは再利用しません。

- 1回の受付や全体の配置換えで使うのは、数ビットから数十ビット程度です。10,000 ビットあれば、数十人規模のイベントを複数回まかなえます
- 画面右上のカードに残りビット数が表示され、少なくなると警告が出ます。足りなくなったら、もう一度実行すると追加されます
- `--maps`（マップ数）、`--qubits`（量子ビット数）、`--backend ibm_fez`（実機の指定）で取得量や実機を変えられます
- 取得したビットの偏りは `python verify_randomness.py` で確認できます（プールは消費しません）

### 6. 起動

```bash
python app.py
```

ブラウザで `http://127.0.0.1:5001` を開いてください（ポートは環境変数 `FLASK_PORT` で変更できます）。

## 📖 使い方

### 1. 会場レイアウトを設定する（事前）

「会場レイアウト」タブで会場を作ります。変更は自動保存されます。

- **□ 四角 / ○ 丸 / ⬠ 多角形**: ツールを選んでキャンバスに描きます（四角と丸はドラッグ、Shift で正方形・正円。多角形は頂点をクリックして始点で確定）
- **● 席を置く**: 席にしたい場所をクリックします（席番号は自動で振られます）
- **Ａ 文字**: 書きたい場所をクリックして文字を入力します（50文字以内）。「選択・移動」で文字をダブルクリックすると書き換えられます
- **→ 矢印 / ／ 線**: ドラッグして描きます（Shift で 45 度刻み）。線は矢じりのない直線です。選択すると両端の丸をドラッグして向きや長さを変えられます
- **選択・移動**: ドラッグで移動、クリックで選択します
- **選択を大きく／小さく**: 選択中の机・文字・矢印・線のサイズを変えます
- **選択を削除**（Delete キー）: 選択中の机・席・文字・矢印・線を削除します（着席中の席は削除できません）
- 文字・矢印・線は合わせて100個までです。受付画面の会場図にも表示されます

### 2. 受付

「受付」タブで名前を入力し、「量子乱数で席を決める」を押すと、空席の中から1席が決まります。

- 決まった席は大きく表示され、会場図でも強調されます
- 名前は、参加者リストの候補をタップするか、直接入力します
- 受付ミスは、着席一覧の「取消」で訂正できます

**参加者リスト（名前の候補）**

受付画面に常に表示されています。1行に1名ずつ入力して「この内容で上書き保存」を押すと、名前の候補になります。着席済みの人は候補から消えます。リストは `data/state.json` に保存され、前回の名前は残りません。

**参加者リストの全員を受付する（一括配置）**

参加者リストの未着席の人を、リストの順に1人ずつ、そのとき残っている空席から量子乱数で決めます（入力欄が未保存でも、その内容を先に保存してから配置します）。

- 受付カードの「量子乱数で席を決める」の下にあるボタンです。人数と消費ビット数の目安が表示されます（例:「（未着席4名・約14ビット消費）」）
- 未着席の人数より空席が少ないときは、誰も配置せずにエラーを表示します（途中まで配置されることはありません）
- 約10秒の全画面演出が流れます。すでに着席している人はその場に残り、未着席の人が会場の外から現れて席に着きます
- 席は押した時点で乱数プールから決まっており、演出は見せ方だけの効果です

**消費ビット数の目安**

ボタンには、そのときの空席数などから見積もった消費ビット数が表示されます（例:「量子乱数で席を決める（約4ビット消費）」）。乱数を引き直すことがあるため、実際の消費は前後します。実際に使ったビット数は結果に表示されます。

**演出**

- 受付では、約3.5秒の演出が流れます。空席が重ね合わさった状態から1席に収縮します
- 演出中に画面をクリックするとスキップできます。OS の「視差効果を減らす」設定がオンの場合や、空席が1つだけの場合は省略されます
- **席は押した時点で乱数プールから決まっており、演出は見せ方だけの効果です**

### 3. 全体の配置換え・リセット

- **全体の配置換え**: 着席済みの全員の席を、空席を含む全座席の中から量子乱数で決め直します
  - 約10秒の全画面演出が流れます（全員が光の玉になって渦を巻き、1人ずつ新しい席に着地して、最後に花火）
  - クリックでスキップでき、「視差効果を減らす」設定では省略されます
- **全体リセット**: 着席状況をすべて消します（会場レイアウトと参加者リストは残ります）
- **CSV 出力**: 席番号・名前・受付時刻をダウンロードします

### データの保存

レイアウト・着席状況・参加者リストは `data/state.json` に保存されるので、サーバーを再起動しても残ります（`.gitignore` 済み）。保存先は環境変数 `STATE_FILE` で変更できます。

## 🧪 量子乱数の仕組み

アプリ内の「仕組み」タブ（`/about`）に、実行した量子回路の図・席の決め方・品質の限界を図入りでまとめています。要点は次のとおりです。

1. **取得（事前）**: `fetch_quantum_pool.py` が、全量子ビットにアダマールゲート（H）をかけて測定する回路を、`SamplerV2` で実機に投入します。1ショットが1つの乱数マップ（量子ビット数ぶんのビット列）で、ショット順に連結して `data/random_pool.json` に保存します
2. **読み出し（受付時）**: 候補が n 個のとき、必要なビット数（`ceil(log2 n)`）だけ未使用ビットを読みます。値が n 以上なら読み捨てて引き直します（棄却サンプリング。剰余を使わないので、どの席も同じ確率になります）
3. **全体の配置換え**: 着席者を1人ずつ、残りの全座席（空席を含む）から同じ方法で選びます

実機の読み出し誤差により、生ビットに 1% 程度の偏りが出ることがあります（`verify_randomness.py` で確認できます）。席決めへの影響は小さいですが、気になる場合は `--maps` を増やして取得し直してください。

### 使える実機について

`fetch_quantum_pool.py` は、アカウント（インスタンス）で使える実機のうち、待ち行列が最も短いものを選びます。日本国内の実機を使うには、その実機を使えるインスタンスの CRN を `.env` の `IBM_QUANTUM_INSTANCE` に設定してください。

## 📝 設定

`.env` または環境変数で次の項目を設定できます。

| 変数 | 説明 |
|---|---|
| `IBM_QUANTUM_TOKEN` | IBM Quantum の API トークン（`fetch_quantum_pool.py` で必須） |
| `IBM_QUANTUM_INSTANCE` | IBM Cloud の CRN（推奨） |
| `IBM_QUANTUM_BACKEND` | 使う実機名（例: `ibm_fez`）。空なら待ち行列が最短の実機を自動選択 |
| `POOL_FILE` | 乱数プールの保存先（既定: `data/random_pool.json`） |
| `STATE_FILE` | 着席状況などの保存先（既定: `data/state.json`） |
| `FLASK_PORT` | ポート番号（既定: 5001） |
| `FLASK_DEBUG` | `1` でデバッグモードを有効化 |

## 🔐 セキュリティ

- API トークンは `.env` で管理し、使うのは取得スクリプトだけです（アプリ本体にトークンは不要です）
- `.env` と `data/`（乱数プール・着席状況）は `.gitignore` で除外しています。乱数プールは、本人だけが読み書きできる権限（600）で保存します
- サーバーは `127.0.0.1` だけで待ち受けます。デバッグモードは `FLASK_DEBUG=1` のときだけ有効です

## 🐛 トラブルシューティング

| 症状 | 対処 |
|---|---|
| 取得スクリプトが接続エラー（SSLError）になる | macOS 付属の Python 3.9（LibreSSL）が原因です。OpenSSL 版の Python 3.10 以上で仮想環境を作り直してください（`brew install python@3.12` → `python3.12 -m venv venv`） |
| 「乱数プールが空です」と表示される | `python fetch_quantum_pool.py` で実機から乱数を取得してください。それまでは疑似乱数で動作し、結果にも「疑似乱数」と表示されます |
| ポート 5001 が使われている | `FLASK_PORT` で別のポートを指定してください（例: `FLASK_PORT=5002 python app.py`） |
| IBM Quantum への接続を確認したい | `python test_connection.py` を実行してください |
