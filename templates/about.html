実行した量子回路

回路はとても単純です。すべての量子ビットに アダマール（H）ゲート をかけてから測定します。

100量子ビット版（図は4本だけ表示）。量子ビット同士をつなぐゲートはなく、各ビットは独立に測定されます。

なぜこれで乱数になるのか

  • 量子ビットは最初 |0⟩ の状態です。
  • Hゲートで (|0⟩ + |1⟩) / √2 の重ね合わせ状態になります。0と1の確率がどちらも50%です。
  • 測定すると、どちらか一方の値に確定します。どちらになるかは量子力学の原理上、事前に決まっておらず、測定するまで誰にも予測できません（疑似乱数のように「種」から計算された値ではありません）。

実機で実際に動く形

実機には「Hゲート」という命令はなく、その機械が持つ基本ゲート（cz, id, rz, sx, x）に変換されて実行されます（Qiskitのトランスパイル）。 Hゲートは「Rz(π/2) → √X → Rz(π/2)」の3つに分解されます。3量子ビットで変換した例:

Hゲート1つが Rz → √X → Rz の3ゲートに置き換わる（3量子ビットで変換した例）。

乱数マップ

回路を 1ショット 実行すると、量子ビット数ぶんのビット列が1つ得られます。これを1つの「乱数マップ」と呼んでいます。 SamplerV2 で shots=100 を指定すると、100個のマップ（各100ビット = 計10,000ビット）を1回のジョブで取得できます（既定値）。

保存形式

data/random_pool.json に、全マップを順番に連結したビット列（bits）と、そこまで使ったビット数（cursor）を保存します。 受付のたびに cursor が進み、サーバーを再起動しても続きから読みます。

受付で席を決める方法

空席が n 席 のとき、0〜n-1 の番号を1つ選び、その番号の空席に着席します。ビット列から n 未満の整数を偏りなく取り出すため、 「棄却サンプリング」を使っています。

例: 空席が7席のとき
  1. 7通りを表すには 3ビット（0〜7）が必要なので、プールの先頭から3ビット読む
  2. 値が 0〜6 ならその番号の席に決定（例: 101 → 5番目の空席）
  3. 値が 7 のときは破棄して、続きの3ビットを読み直す

「乱数 mod 7」で割り当てると一部の席が当たりやすくなってしまうため、あえて読み捨てています。読んだビット（捨てた分も含む）は再利用しません。

  • 受付: 空席から1席を選びます。
  • 全体の配置換え: 着席者ごとに、全座席（空席を含む）から1席ずつ同じ方法で選びます（フィッシャー–イェーツ方式のシャッフル）。
  • 1回あたりの消費量: 十数ビット程度。100ビットのマップ1個で数人ぶんが決まります。

品質と限界（正直な説明）

  • 実機にはわずかな偏りがあります。読み出し誤差などにより、「1」の割合が50%から1%程度ずれることがあります。席決めへの影響は小さいですが、 python verify_randomness.py で偏り（1の割合・連の数・分布）を確認できます。
  • 「受付の瞬間に測定」ではなく「事前に測定した値を使う」方式です。測定自体は量子コンピューターで行われた本物の乱数ですが、 ファイル data/random_pool.json を見られる人には、これから決まる席を予測できてしまいます。ファイルは本人のみ読める権限（600）で保存しています。
  • プールが空になると疑似乱数に切り替わります。その場合は結果カードに「疑似乱数」と表示され、警告が出ます。
